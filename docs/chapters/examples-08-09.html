Example 8 & 9: Multinomial GLMMs with and without proportional odds

Author

Quentin D. Read, Bruce A. Craig, Philip M. Dixon, and Walter W. Stroup

NoteGLMM Challenge

Ordered categorical data are widespread in the agricultural and natural resource sciences. They typically arise in contexts where an underlying continuous variable is difficult or impossible to measure, such as disease severity or body condition. Think of a phenotype like disease severity scored on a scale from 1 to 5. In many cases, fitting a model assuming normally distributed error results in poor inferential and predictive performance. A GLM using a multinomial distribution and cumulative logit link function is a much better option (GLMM if random effects are required by the study design) because it naturally accommodates the categorical nature of the response. The multinomial cumulative logit GLM generalizes the binomial logit GLM to multiple ordered categories. In a multinomial cumulative logit model with C response categories, there are C - 1 linear predictors, each with their own link function. Link function c maps the probability of the response being in the cth category (c = 1, 2, … C) or lower, conditioned on fixed and random effects, to the log odds scale.

An essential but commonly overlooked assumption when fitting multinomial cumulative logit models is the proportional odds assumption. Most software implementations of the multinomial cumulative logit model assume proportional odds by default. The proportional odds assumption means that no predictor variable, whether fixed or random, has a disproportionate effect on any specific category of the outcome variable. The odds ratios associated with the threshold between the cth and c + 1th category are the same across all the treatments and blocks. Under the proportional odds assumption, the odds ratio between any pair of treatments is the same for the odds of being less than or equal to category 1, the odds of being less than or equal to category 2, and so on (i.e., the odds are “proportional”). Operationally, this means that the fitted linear predictors in the proportional odds model may have different intercepts for each category of the response variable, but common fixed and random effect coefficients across all categories. Put informally, proportional odds means that we can make statements like “treatment A is associated with 50% higher odds of being in a greater category than treatment B” because the effects of each treatment don’t depend on exactly which ordinal category is being considered.

Yet, the proportional odds assumption need not always hold. In many real-world cases, variables do not have consistently positive or negative effects on the outcome; for example, a particular treatment may be associated with increased odds of the response being in low and high categories, but decreased odds of the response being in intermediate categories. If a proportional odds model is fit in an inappropriate context, nonsensical results and poor model fit ensue. In this document, we present two example datasets, one simulated with proportional odds and the other simulated with non-proportional odds. We survey the options for fitting multinomial cumulative logit models to ordinal data with and without the proportional odds assumption in R and SAS, including both Frequentist and Bayesian alternatives, and identify gaps where work is needed to make high-quality implementations available for users of both software platforms.

Proportional odds example

Study Design & Data Generation Process

The first example dataset was originally presented in Generalized Linear Mixed Models, 2nd edition, Section 14.3 (Stroup et al. (2024)).

The research question is: Does disease severity differ between six different treatments? Disease severity is a categorical variable collected on an ordinal scale with three levels: slight, moderate, and severe.

In this study, treatments were organized in two sets, with set A consisting of treatments 0, 1, 2 and set B consisting of treatments using 3, 4, 5. The study was done at ten independent clinics (blocks) using a disconnected incomplete block design. Five clinics were randomly assigned to treatment set A, and the other five to treatment set B. At each clinic, patients were divided into three units, each containing variable numbers of patients (ranging from 14 to 35 with median 26.5). For each clinic assigned to treatment set A, the units were randomly assigned to receive treatments 0, 1, and 2. For clinics with treatment set B, the units were assigned to treatments 3, 4, and 5. The eventual outcome was disease severity for each patient, scored on the three-category ordinal scale.

Here we assume that the effects of treatment are fixed, and the effects of block and unit within block after accounting for treatment are random. This results in the following ANOVA shell, which summarizes the complete data generation process.

NoteNotes on study design

Note that this ANOVA shell assumes the experimental unit, or unit of replication for treatment, is Unit within Clinic (a group of patients assigned to the same treatment within a clinic). Meanwhile, the observational unit on which the ordered categorical response is recorded is the individual patient. However, the models are fit assuming that the experimental unit is the individual. Preliminary analyses using Frequentist model fitting algorithms in both R and SAS found a zero or near-zero variance of the unit within clinic random intercept. This indicates that there was no evidence for unit effects after accounting for treatment, effectively dropping that term from the model. The Bayesian model with a weakly regularizing prior on the random effect standard deviation gives a positive estimate for the unit within clinic variance, although it has only a minor effect on the inference. Alternatively, the variance component estimate for unit within block can be allowed to be negative, for example by using the nobound option in SAS PROC GLIMMIX. The main consequence for inference is that the number of degrees of freedom is much higher when we assume independent assignment of treatments to individual patients within clinics.

Another thing to notice here is that treatments are organized in disconnected sets: treatments 0, 1, and 2 are only present at five of the ten clinics (blocks), and treatments 3, 4, and 5 at the other. Contrasts between treatment pairs that do not occur together within the same set, such as 0 vs. 3, can only be estimated if clinic is fitted as a random effect.

Statistical Model

We fit the proportional-odds cumulative logit GLMM to this dataset.

Linear predictors

\[\boldsymbol\eta_{cij} = \eta_{c} + \tau_{i} + b_{j}\]

Here, \(\boldsymbol\eta_{cij}\) denotes the linear predictor for the cth category of the ordinal response (\(c = 0, 1\)) for the ijth treatment-block combination, \(\eta_c\) is the intercept for the cth category, enforcing that \(\eta_0 < \eta_1\), and \(\tau_i\) and \(b_j\) denote effects of the ith treatment and jth block, respectively. Note that because there are three response categories, we have two linear predictors: one fewer than the number of categories. Also note that the intercept \(\eta_c\) is indexed with c, but the treatment and block effect terms are not. That is the definition of the proportional odds model: the fixed and random effects other than the intercept are the same across categories.

Distributions

\[y_{\text{slight}, ij}, y_{\text{moderate}, ij}, y_{\text{severe}, ij} | b_{ij} \sim \text{Multinomial}(N_{ij}, \pi_{\text{slight}, ij}, \pi_{\text{moderate}, ij}, \pi_{\text{severe}, ij})\]

\[b_j \text{ i.i.d. } N(0, \sigma^2_b)\]

For each of the experimental units identified by the ijth treatment-block combination, the number of patients diagnosed with each of the three disease severity levels follows a multinomial distribution with parameter \(N_{ij}\) being the total number of patients in the ith treatment and jth clinic and three \(\pi_{c,ij}\) parameters, each one being the probability of the cth disease severity class in the ijth treatment-clinic combination. The three \(\pi_{c,ij}\) values must sum to 1 for each ij combination; they are not expressed as cumulative probabilities.

Link function

\[\boldsymbol\eta_{0ij} = \log \Big( \frac {\pi_{\text{slight}, ij}} {1 - \pi_{\text{slight}, ij}} \Big)\]

\[\boldsymbol\eta_{1ij} = \log \Big( \frac {\pi_{\text{slight}, ij} + \pi_{\text{moderate}, ij}} {1 - (\pi_{\text{slight}, ij} + \pi_{\text{moderate}, ij})} \Big)\]

The cumulative multinomial probabilities are converted to the log-odds or logit scale using the cumulative logit link function. The first equation above is the log-odds of the outcome being slight or less, and the second is the log-odds of the outcome being moderate or less (a function of the sum of the probability of slight and probability of moderate). A third link is not needed because the probability of severe or less is 1.

Graphical test of proportional odds assumption

There are several different ways to test the proportional odds assumption. The following graphical method was developed by Harrell (Harrell (2015)) and later expanded upon using a hybrid Bayesian/frequentist approach (Harrell (2022)). An example of the test can be found in UCLA Statistics’ tutorial on ordinal logistic regression (Group (n.d.)). This test is done before fitting the multinomial cumulative logit model.

To do Harrell’s graphical test, we use the raw data to calculate the difference in the observed cumulative log odds of successive categories within each group. If, for each category threshold, the differences between the log-odds are roughly similar across all the groups, this indicates that each group’s effect on the log-odds is roughly similar regardless of threshold. If this is the case, then the proportional odds assumption is tenable. Put informally, proportional odds means that we can make statements like “treatment A is associated with 50% higher odds of being in a greater category than treatment B” because the effects of each treatment don’t depend on exactly which ordinal category is being considered.

In the example below, performing the graphical test is equivalent to doing a series of binomial regressions with treatment as a fixed effect, temporarily ignoring the random effect of block. (A similar test could be done to see whether the odds are proportional across the blocks, in addition to the one for treatments shown below.)

To implement the graphical test in R, first load all necessary packages. Import data. Set factor and ordered factor variables where necessary.

The below code fits the multinomial cumulative logit model using clmm() from the R package ordinal (Christensen (2023)). Frequentist implementation: SAS PROC GLIMMIX

The Frequentist model is implemented in SAS PROC GLIMMIX as shown below. Note that the coefficient estimates and standard errors are the same as in R’s ordinal::clmm(). However the test statistics associated with the fixed effects are t-statistics, with the containment method used for the degrees of freedom. This is the number of observations - rank([X Z]), or the rank of the concatenated model matrices for the fixed and random effects.

The following SAS code can be used to fit the Frequentist proportional odds model; the DATA step is not shown here. See Appendix A for full SAS code and output.

proc glimmix data=ratings method=laplace;
  class blk trt (ref = "0");
  model rating(order=data)=trt/dist=multinomial solution oddsratio;
  random intercept / subject=blk solution;  
  estimate 'slight, t=0' intercept 1 0 trt 0 0 0 0 0 1,
           'moderate, t=0' intercept 0 1 trt 0 0 0 0 0 1,
           'slight, t=1' intercept 1 0 trt 1 0 ,
           'moderate, t=1' intercept 0 1 trt 1 0,
           'slight, t=2' intercept 1 0 trt 0 1 0,
           'moderate, t=2' intercept 0 1 trt 0 1 0, 
           'slight, t=3' intercept 1 0 trt 0 0 1 0,
           'moderate, t=3' intercept 0 1 trt 0 0 1 0,
           'slight, t=4' intercept 1 0 trt 0 0 0 1 0,
           'moderate, t=4' intercept 0 1 trt 0 0 0 1 0,
           'slight, t=5' intercept 1 0 trt 0 0 0 0 1 0,
           'moderate, t=5' intercept 0 1 trt 0 0 0 0 1 0 / ilink bycat;
  freq y;
run;

Bayesian implementation: Stan via R brms::brm

The brms package in R (Bürkner (2017)) can be used to generate a Stan program (Team (2026)) that will fit a Bayesian version of the model using Hamiltonian Monte Carlo to sample the joint posterior distribution of the parameters. It is necessary to convert the data to a long form with one trial per row.

The likelihood is identical to the Frequentist models above. In addition, the following weakly informative prior distributions are assumed.

  • \(\eta \sim N(0, 10)\)
  • \(\tau \sim N(0, 10)\)
  • \(\sigma_b \sim Gamma(1, 1)\)

Note that the model is parameterized using the standard deviation of the random block intercept (class = sd) rather than the variance.

The joint posterior distribution of the model parameters is sampled using Hamiltonian Monte Carlo (HMC), with four Markov chains. Each Markov chain includes 1000 warmup iterations in which the hyperparameters of the HMC algorithm are tuned, followed by 1000 sampling iterations. The warmup iterations are not considered part of the posterior distribution, therefore there are 4000 posterior samples total. For practical purposes, when very accurate characterization of the tails of the posterior distribution is needed, more samples should be taken.

ex8long <- ex8 %>% 
  group_by(Block, Trt) %>%
  reframe(Rating = rep(Rating, Y)) 

fit8brm <- brm(Rating ~ Trt + (1 | Block),
               data = ex8long,
               family = cumulative(link = 'logit', threshold = 'flexible'),
               prior = c(
                 prior(normal(0, 10), class = Intercept),
                 prior(normal(0, 10), class = b),
                 prior(gamma(1, 1), class = sd)
               ),
               chains = 4, cores = 4, iter = 2000, warmup = 1000, seed = 202,
               file = '../data/example_08_brmfit', file_refit = 'on_change'
               )

Post-model-fitting tests of proportional odds assumption

In addition to the qualitative graphical test we showed above, another way to test the proportional odds assumption is to fit the model relaxing the proportional odds assumption and compare the models with a likelihood ratio test. This can be done in R using ordinal::clmm2(). Unfortunately, ordinal::clmm() does not support relaxing the proportional odds assumption (see the non-proportional odds example below for further discussion).

proportional_odds_model <- clmm2(Rating ~ Trt,
                                 random = Block,
                                 weights = Y,
                                 link = 'logistic',
                                 threshold = 'flexible',
                                 data = ex8)
nonproportional_odds_model <- clmm2(Rating ~ Trt,
                                    random = Block,
                                    nominal = ~ Block,
                                    weights = Y,
                                    link = 'logistic',
                                    threshold = 'flexible',
                                    data = ex8)

Lastly, the Brant-Wald test is a type of Wald Chi-squared test of the null hypothesis that the proportional odds assumption holds (Brant (1990)). In R, it is implemented in brant::brant() (Schlegel and Steenbergen (2020)) and gofcat::brant.test() (Ugba (2022)), which yield identical results (not shown). These packages do not have methods for the mixed model case, only for fixed-effects models such as those fit with MASS::polr() (Venables and Ripley (2002)) and ordinal::clm(). Therefore we refit the model with only the fixed effect of treatment before doing the Brant-Wald test. Including block as a fixed effect would be acceptable for testing whether the proportional odds assumption holds across blocks. Another thing to note is that brant() and brant.test() ignore the weights argument in the model, so we need to refit the model using the long-form disaggregated version of the data that was also used above for fitting the brm() model.

Below we see that the null hypothesis of proportional odds with respect to treatment is not rejected in the omnibus case nor for any of the individual treatments, supporting the proportional odds assumption.

fit8clm <- clm(
  Rating ~ Trt,
  link = 'logit',
  threshold = 'flexible',
  data = ex8long
)

gofcat::brant.test(fit8clm)

Estimating treatment means

In SAS PROC GLIMMIX, the cumulative probabilities of each disease severity rating class threshold for each treatment, not conditioned on any of the random effects, are obtained using the estimate statement within the modeling procedure. Note that PROC GLIMMIX does not support the calculation of these marginal means for multinomial models. However, the same estimates can be obtained more concisely, without having to explicitly construct the linear combinations of predictors, with PROC PLM as follows (results not shown):

proc glimmix data=ratings method=laplace;
  class blk trt (ref = "0");
  model rating(order=data)=trt/dist=multinomial;
  random intercept / subject=blk;   
  freq y;
  store fit;
run;

proc plm restore=fit;
  lsmeans trt / ilink;
run;

In R ordinal::clmm(), the probabilities are obtained using emmeans::emmeans() (Lenth (2025)). The function emmeans() offers a much wider variety of computations of treatment means for multinomial models than SAS PROC PLM. While the SAS procedure only provides the means in the form of cumulative probabilities for each threshold, the mode argument of emmeans() can be used to produce different quantities. However, the SAS NLMEANS macro, version 3.0 or greater (Institute (n.d.)), may be used to obtain the same variety of transformations of the treatment means as emmeans(), by supplying the transformations explicitly through the keyword fdata. See example below. In both the NLMEANS macro and in emmeans(), the standard errors of the different transformations are calculated using the delta method.

Use mode = 'cum.prob' and specs = ~ cut | Trt to obtain the cumulative probabilities at each threshold, equivalent to SAS. (Here and in some subsequent code examples, the output is not displayed by default and may be expanded by clicking.)

Discussion of degrees of freedom

All of the above predictions obtained by emmeans() are accompanied by asymptotic 95% confidence intervals based on the z-distribution; no attempt is made to estimate the degrees of freedom. This is also the case for the parameter estimate summary obtained with the summary() method of clmm objects in R.

In contrast, SAS PROC GLIMMIX by default uses containment degrees of freedom. The way the containment degrees of freedom are calculated may not be immediately obvious because the experimental design is disconnected, with confounding between block and treatment. Treatments 0, 1, and 2 always appear together in five of the ten incomplete blocks, while treatments 3, 4, and 5 always appear together in the other five. According to PROC GLIMMIX, the Rating intercepts have 8 degrees of freedom (10 blocks - 2 intercepts), not 9 as the ANOVA shell would indicate. The treatment coefficients have 768 degrees of freedom. One might expect 767 (783 observations - 16 parameters estimated) but after estimating the treatment effects, one fewer parameter is needed to identify all the block effects, thus we obtain 768.

It is important to be aware that in a disconnected design such as this one, not all pairwise treatment contrasts should have the same number of degrees of freedom associated with them. The difference between treatments that occur in the same block, such as treatment 0 versus treatment 1, is purely a within-block estimate; block variance does not enter into the standard error of that difference and the degrees of freedom should be 768 (the error df). But for between-block differences, such as treatment 0 versus treatment 3, the degrees of freedom should be a Satterthwaite combination of error df and block df. However, the SAS containment method uses error df for both types. In general, if the incomplete block design were connected, treatment differences would combine within- and between-block information (Satterthwaite df); but the degrees of freedom would only be the same for all differences if the incomplete block design were perfectly balanced.

For disconnected designs, pairwise differences between means that never appear together in the same block cannot be estimated at all if block is treated as a fixed effect. But if block is random, the differences can be estimated. Therefore it is crucial that block is treated as a random effect if it is desired to estimate all pairwise treatment differences in a disconnected design. (Stroup et al. (2018); section on spurious non-estimability).

Note: Because PROC GLIMMIX uses t-statistics to estimate the confidence intervals of the estimated means, it is consequential whether we assume independent assignment of treatments to the individual patients, or assignment to groups of patients (the degrees of freedom is much lower in the latter case). Because emmeans() uses large-sample statistics and asymptotic confidence intervals, if we do include the unit within block random intercept, because it is estimated as near zero, the confidence intervals are equivalent regardless. See note above the ANOVA shell.

Statistical Model

We will fit the proportional odds and non-proportional odds cumulative logit GLMMs to this dataset, to illustrate the importance of relaxing the proportional odds assumption.

Linear predictors

\[\boldsymbol\eta_{cij} = \eta_{c} + \nu_{ci} + g_{j} + gv_{ij}\]

Here, \(\boldsymbol\eta_{cij}\) denotes the cth linear predictor (\(c = 0, 1\)) for the ijth grower-variety combination, \(\eta_c\) is the intercept for the cth linear predictor, \(\nu_{ci}\) is the variety effect for the cth linear predictor, and \(g_j\) and \(gv_{ij}\) are the random effects of grower and variety nested within grower, respectively. The key difference between this and the previous model is that now not only the intercept, but also the variety effect, is indexed with c. Now, the fixed effect of variety is not the same for each category threshold’s linear predictor. It is also possible to relax the proportional odds assumption for the random terms, but in this case we are assuming the effect of grower and variety within grower on each of the thresholds is the same. Only two variance components will be estimated overall, rather than two for each category threshold.

Distributions

\[y_{\text{A}, ij}, y_{\text{B}, ij}, y_{\text{C}, ij} | b_{ij} \sim \text{Multinomial}(N_{ij}, \pi_{\text{A}, ij}, \pi_{\text{B}, ij}, \pi_{\text{C}, ij})\]

\[g_j \text{ i.i.d. } N(0, \sigma^2_g)\]

\[gv_{ij} \text{ i.i.d. } N(0, \sigma^2_{gv})\]

Identically to the previous example, for each of the experimental units (grower-variety combinations), the counts of plants in the ijth grower-variety combination rated with each of the three quality ratings follows a multinomial distribution with parameter \(N_{ij}\) being the total number of plants in the ijth grower-variety combination and three \(\pi_{c,ij}\) parameters, each one being the probability of the cth quality rating class in that grower-variety combination. As before, the three \(\pi_{c,ij}\) values must sum to 1.

Link function

\[\boldsymbol\eta_{0ij} = \log \Big( \frac {\pi_{\text{A}, ij}} {1 - \pi_{\text{A}, ij}} \Big)\]

\[\boldsymbol\eta_{1ij} = \log \Big( \frac {\pi_{\text{A}, ij} + \pi_{\text{B}, ij}} {1 - (\pi_{\text{A}, ij} + \pi_{\text{B}, ij})} \Big)\]

The link functions have identical forms to those from the proportional odds model.

Frequentist implementation: SAS PROC NLMIXED

An implementation of the statistical model is possible in SAS. Because PROC GLIMMIX does not support relaxing the proportional odds assumption, we use PROC NLMIXED. This requires explicitly writing out the equations for the linear predictors and the inverse link functions. Starting values for the parameters must also be provided. In addition, the linear predictor term must be explicitly constrained to be greater than zero. If the term is less than or equal to zero, it is set to a small positive value (1 × 10-8).

Here, qpoints=1 in the procedure statement sets the number of quadrature points to 1, meaning that the Laplace approximation is used.

Only the PROC GLIMMIX code and not the preceding data step is shown here, and only an excerpt of the output is shown. Full code and output is in Appendix C.

proc nlmixed data=Numeric_ratings qpoints=1;
  parms int_0=-0.5 int_1=0.5 tau_01=0 tau_11=0 tau_02=0 tau_12=0 sdb=0.5 sdbt=0.25; 
  eta_0=int_0+(variety=1)*tau_01+(variety=2)*tau_02+blk_j+bt_1j*(variety=1)+bt_2j*(variety=2)+bt_3j*(variety=3);
  eta_1=int_1+(variety=1)*tau_11+(variety=2)*tau_12+blk_j+bt_1j*(variety=1)+bt_2j*(variety=2)+bt_3j*(variety=3);
  pi_0=1/(1+exp(-eta_0));
  pi_1=1/(1+exp(-eta_1))-1/(1+exp(-eta_0));
  pi_2=1-pi_0-pi_1;
  /* Y=1 => rating A */
  /* Y=2 => rating B */
  /* Y=3 => rating C */
  if y=1 then pi=pi_0;
  else if y=2 then pi=pi_1;
  else pi=pi_2;
  p = (pi>0 and pi<=1)*pi + (pi<=0)*1e-8 + (pi>1);

Frequentist implementation: R TMB

To our knowledge, no “off-the-shelf” Frequentist model fitting package in R currently supports relaxing the proportional odds assumption in a flexible enough context to fit this model. See below for more details on this. However, it is possible to fit the model using the Template Model Builder (TMB; Kristensen et al. (2016)). The likelihood is specified similarly to PROC NLMIXED but written using a C++ model template. The C++ program is compiled. Following that, an R script is used to put the data into an appropriate format, define starting values for the parameters, and estimate the model. There are also many additional estimates specified: the marginal probabilities of each rating for each variety as well as the same values expressed as log odds, the contrasts for the joint hypothesis tests, and the variance components. Laplace approximation is used as the integration method. Here we use a quasi-Newton method (BFGS) for optimization, similar to the PROC NLMIXED example.

Bayesian implementation: Stan via R brms::brm

A proportional odds model, which we already know to be inappropriate, may be fit using Stan, via the R interface brms::brm(), with similar syntax to the previous brms example. The model formula specifies a fixed effect for variety, a random intercept for each grower, and a random intercept for variety nested within grower, with no covariance between the random effects. The cumulative response family with logit link and flexible category thresholds is specified. Weakly informative prior distributions are assumed:

  • \(\eta \sim N(0, 10)\)
  • \(\nu \sim N(0, 10)\)
  • \(\sigma_g \sim Gamma(1, 1)\)
  • \(\sigma_{gv} \sim Gamma(1, 1)\)

The HMC algorithm is run using four Markov chains, with 1000 discarded warmup iterations and 1000 sampling iterations per chain, for a total of 4000 samples from the joint posterior distribution.

Note that the control parameter adapt_delta is set to 0.95, higher than the default value of 0.8. This reduces the sampler’s step size, making it explore the posterior slightly less efficiently, but eliminating divergent transitions.

fit9brm_po <- brm(
  Rating ~ Variety + (1 | Grower) + (1 | Variety:Grower),
  family = cumulative(link = 'logit', threshold = 'flexible'),
  prior = c(
    prior(normal(0, 10), class = Intercept),
    prior(normal(0, 10), class = b),
    prior(gamma(1, 1), class = sd)
  ),
  data = ex9long,
  chains = 4, cores = 4, iter = 2000, warmup = 1000, seed = 130,
  control = list(adapt_delta = 0.95),
  file = '../data/example_09_po_brmfit', file_refit = 'on_change'
)

The non-proportional odds model has identical syntax except for the fixed effect term in the model formula: there, cs(Variety) indicates category-specific effects on Variety. This relaxes the proportional odds assumption by allowing the two linear predictors to have different variety effects.

Comparison of estimates

Below is a graphical comparison of the estimates for the Frequentist implementations in SAS PROC NLMIXED and R TMB versus the Stan brms::brm() Bayesian implementation. In all cases these are marginal estimates not conditioned on the random effects. The R and SAS Frequentist implementations are nearly identical in their point estimates. The 95% confidence intervals differ for the following reason. In both cases, confidence intervals were constructed using the number of parameters in the model (8) as the degrees of freedom. However, the SAS confidence intervals were constructed by simply multiplying the standard error by the corresponding quantile of the t-distribution and adding and subtracting from the point estimate on the probability scale. This leads to intervals that are symmetrical on the probability scale but asymmetrical on the log-odds scale, and which may overlap 0 or 1. In fact here several of the intervals do overlap 0. We constructed the confidence intervals for the TMB estimates in a more appropriate manner, by obtaining the confidence interval endpoints on the log-odds scale and inverse transforming to the probability scale.

The same reasons discussed for the previous example apply to explain why there are differences between the Frequentist and Bayesian estimates and their 95% confidence / credible intervals. (Note that the 95% confidence intervals constructed on the log scale and inverse transformed agree more closely with the Bayesian credible intervals.) Regardless of those minor differences, all models fit the data well due to the flexibility gained by relaxing the proportional odds assumption.

Post-fitting tests of proportional odds assumption

There are other tests of the proportional odds assumption that can be done after model fitting (Stroup et al. (2024)). The first approach is model comparison: after fitting the model that relaxes the proportional odds assumption, we may compare fit statistics between the models with and without the assumption. Of course, this is not possible if one of the models is not implemented in a particular software platform. For SAS users, Stroup et al. (2024) recommend fitting the generalized logit model in PROC GLIMMIX; although this model assumes unordered categories, it has the same linear predictors as the non-proportional odds model with ordered categories. The fit statistics for this model can be compared to the proportional-odds fit statistics from PROC GLIMMIX; if the proportional odds model is preferred, the user may avoid the lengthy process of writing PROC NLMIXED code.

The second approach is to do formal hypothesis tests of the null hypothesis that \(v_{0i} = v_{1i}\) for each of the varieties indexed with \(i\). In this particular case because there are only two category thresholds, there is only one test per group (variety), but there would be more tests per group when there are four or more categories. A similar test could be done to compare random effect variances between category thresholds, if the proportional odds assumption is also being relaxed for random terms in the model. Rejection of any of the null hypotheses would be evidence that the proportional odds assumption is violated, justifying fitting the model that relaxes the assumption.

Discussion of model implementations in software

To our knowledge there is no satisfactory Frequentist implementation of the above model currently available in any R package, that does not require the user to fully specify the likelihood from scratch, as was necessary in both SAS PROC NLMIXED and R TMB. Why not? To accommodate the violation of the proportional odds assumption, the model must include category-specific effects, sometimes referred to as nominal effects. In addition, the model must also include multiple random effects. The best-known general-purpose Frequentist GLMM packages in R (lme4 and glmmTMB; Bates et al. (2015); Brooks et al. (2017)) do not support cumulative logistic models at all, at least not without extensive customization similar to what was done in PROC NLMIXED for this example. Plans are afoot, as of the time of this writing, to add cumulative logistic models to glmmTMB, and potentially add support for relaxing the proportional odds assumption in the future.

We searched extensively for other R packages that might implement the model. The R package ordinal implements cumulative logistic mixed models. It implements cumulative logistic mixed models with category-specific effects (i.e., allowing violation of proportional odds) in the clmm2() function, and it implements cumulative logistic mixed models with multiple random effects in the clmm() function. Unfortunately, though, both category-specific effects and multiple random effects are not implemented within the same function. Furthermore, the package is not under active development, so it is unlikely that these features will be combined.

There are a few other R packages that initially showed some promise, including mixcat (Papageorgiou and Hinde (2012)), mclogit (Elff (2025)), and mgcv (Wood (2017)). The mixcat and mclogit packages have relatively poor documentation. We were unable to reproduce the model in either of them. The mixcat package in particular lacks most of the standard R GLMM methods like predict() and simulate(). Therefore even if the model can be fit with mixcat, it would not be integrated with packages such as emmeans and DHARMa, making it not very useful. In mgcv, a GAMM fitting package, there is a multinomial response family and the ability to fit random effects using the spline syntax. However, we were unable to reproduce the desired model because the multinom() family in mgcv is an unordered multinomial, rather than an ordered multinomial with relaxation of proportional odds assumption for the fixed effects. The ocat() (ordered categorical) family in mgcv also differs in important respects from our desired model.

Frequentist implementations: paths forward

It is unlikely that additional features will be added to SAS PROC GLIMMIX, thus for the foreseeable future SAS users that want to fit a non-proportional odds multinomial GLMM will need to use PROC NLMIXED and fully specify the likelihood “by hand.” While this is a satisfactory solution for savvy users, it is a relatively error-prone process that may be daunting to inexperienced users.

In R, the situation is similar. Few users are willing or able to fully specify the likelihood, as required by TMB. However it is possible to create user-defined response families for GLMMs using a package such as glmmTMB (Brooks et al. (2017)), glmmADMB (Fournier et al. (2012)), or GLMMadaptive (Rizopoulos (2025)). The multinomial could be added, which would allow constructing a cumulative logit model with category-specific effects and nested random effects. The Bayesian solutions described above, whether it be the off-the-shelf version provided by brms or a Stan program with the likelihood fully specified by the user similarly to PROC NLMIXED (see Appendix F), are also suitable. They result in similar coefficient estimates to the maximum likelihood methods when weakly informative prior distributions are used. However, if a Frequentist implementation in R is desired that does not require constructing a fully customized likelihood, the most promising avenue is to add that functionality to glmmTMB or another general-purpose GLMM package. The above TMB template could be used as a starting point, if it is modified into a more general version that implements the matrix algebra instead of manipulating individual scalar coefficients.

Appendix B: Quantitative comparison of implementations of proportional odds model

The following is a comparison of parameter estimates generated by fitting the multinomial proportional odds model to the example dataset using all available methods of estimation:

  • In R ordinal::clmm() we may only choose the number of quadrature points for adaptive Gaussian quadrature. In the case of 1 quadrature point we get the Laplace approximation. Here I show results for 1, 5, and 10 quadrature points.
  • In SAS PROC GLIMMIX, we may choose the Laplace approximation, adaptive quadrature where the number of quadrature points is chosen adaptively, or from four different pseudo-likelihood methods. Here I show results for MSPL and MMPL, because RSPL and RMPL did not converge.

The SAS model fit by PROC GLIMMIX with method=laplace results in identical coefficient estimates and standard errors to ordinal::clmm(), fit using the default Laplace approximation, in R. The quadrature methods from both R ordinal and from SAS result in very similar coefficient estimates. However, the two pseudo-likelihood methods fit by PROC GLIMMIX are not identical. The coefficients differ from the quadrature methods at the second or third significant figure. In addition, they show a higher level of shrinkage, with the absolute values of the coefficients being closer to zero. In this case, the consequences for inference would be fairly minimal. See Stroup & Claassen for a more in-depth discussion. It is important for this class of models, as for all the other GLMMs discussed in this guide, to be aware of the potential for results to differ based on method of estimation, and to make an informed choice.

The pseudo-likelihood methods allow a wider variety of degrees of freedom adjustments, which can be obtained by including ddfm=satterth (Satterthwaite) or ddfm=kr (Kenward-Rogers) as an additional option in the model statement.

Qualitatively, the Bayesian coefficient estimates from brms::brm() are similar to the Frequentist estimates; of course, the Bayesian estimates will not agree exactly because (1) weakly informative priors are used, which have a minor influence on the posterior estimates, (2) Monte Carlo is stochastic and a finite number of samples are taken from the posterior distribution, from which we take the median to get the point estimates of the parameters, (3) the Bayesian credible intervals propagate uncertainty of the variance components, thus they would differ slightly from the Frequentist confidence intervals even if we used flat priors and took enough MC samples to reduce MC sampling error to zero, and (4) for parameters that have a right-skewed posterior distribution, using the mean as the point estimate will result in a higher value than the mode. Point 4 is the primary reason why the Bayesian point estimate of the block variance is much larger than the estimate from the Frequentist methods.

Appendix D: Full C++ and R code and output for non-proportional odds model fit with Template Model Builder

This is the model written as a C++ template:

// ------------------------------------------------------------
//  Multinomial (3-category) mixed model
//  Uses TMB (Template Model Builder)
// ------------------------------------------------------------
#include <TMB.hpp>

template<class Type>
Type objective_function<Type>::operator() ()
{
  /* --------------------  DATA  -------------------- */
  DATA_INTEGER(N);                    // # observations
  DATA_VECTOR(y);                     // rating (1,2,3)
  DATA_IVECTOR(variety);              // 1‑3
  DATA_IVECTOR(grower);               // block id, 0‑based

  /* -----------------  FIXED EFFECTS  ----------------- */
  PARAMETER(int_0);   // intercept for category 0 (A)
  PARAMETER(int_1);   // intercept for category 1 (B)
  PARAMETER(tau_01);  // variety‑1 shift for η0
  PARAMETER(tau_11);  // variety‑1 shift for η1
  PARAMETER(tau_02);  // variety‑2 shift for η0
  PARAMETER(tau_12);  // variety‑2 shift for η1
  PARAMETER(log_sdb);   // log‑sd of block random intercept
  PARAMETER(log_sdbt);  // log‑sd of block‑by‑treatment random slopes

  /* -------------------  RANDOM  -------------------- */
  // One random effect per Grower (block)
  PARAMETER_VECTOR(blk);   // block intercept
  PARAMETER_VECTOR(bt1);   // block × variety‑1 slope
  PARAMETER_VECTOR(bt2);   // block × variety‑2 slope
  PARAMETER_VECTOR(bt3);   // block × variety‑3 slope

  /* -----------------  TRANSFORMS  ------------------ */
  Type sdb  = exp(log_sdb);       // σblk
  Type sdbt = exp(log_sdbt);      // σblk×trt

  /* -------------- NEGATIVE LOG-LIKELIHOOD ---------- */
  Type nll = 0.0;

  for (int i = 0; i < N; ++i) {
    int gi = grower[i];                 // block index (0-based)
    int vi = variety[i];                // 1, 2, or 3

    // linear predictors for the two cumulative logits
    Type eta0 = int_0 + (vi == 1) * tau_01 + (vi == 2) * tau_02 + blk[gi] + bt1[gi] * (vi == 1) + bt2[gi] * (vi == 2) + bt3[gi] * (vi == 3);
    Type eta1 = int_1 + (vi == 1) * tau_11 + (vi == 2) * tau_12 + blk[gi] + bt1[gi] * (vi == 1) + bt2[gi] * (vi == 2) + bt3[gi] * (vi == 3);

    // category probabilities (cumulative-logit formulation)
    Type pi0 = 1.0 / (1.0 + exp(-eta0));
    Type pi1 = 1.0 / (1.0 + exp(-eta1)) - pi0;
    Type pi2 = 1.0 - pi0 - pi1;

    // select the probability that matches the observed rating
    Type pi = (y[i] == 1) ? pi0 : ((y[i] == 2) ? pi1 : pi2);
    // protect against log(0)
    pi = (pi > 0 && pi < 1) ? pi : (pi <= 0 ? Type(1e-8) : Type(1.0));

    nll -= log(pi);
  }

  // random-effect contributions (independent Normal(0,σ))
  nll -= sum(dnorm(blk,  Type(0), sdb,  true));
  nll -= sum(dnorm(bt1,  Type(0), sdbt, true));
  nll -= sum(dnorm(bt2,  Type(0), sdbt, true));
  nll -= sum(dnorm(bt3,  Type(0), sdbt, true));

  /* ---------------- POST‑HOC REPORTS --------------- */
  // fixed-effect probabilities for each variety 
  ADREPORT( 1.0/(1.0+exp(-(int_0 + tau_01))) );                                    // A, var 1
  ADREPORT( 1.0/(1.0+exp(-(int_1 + tau_11))) - 1.0/(1.0+exp(-(int_0 + tau_01))) ); // B, var 1
  ADREPORT( 1.0 - 1.0/(1.0+exp(-(int_1 + tau_11))) );                              // C, var 1

  ADREPORT( 1.0/(1.0+exp(-(int_0 + tau_02))) );                                    // A, var 2
  ADREPORT( 1.0/(1.0+exp(-(int_1 + tau_12))) - 1.0/(1.0+exp(-(int_0 + tau_02))) ); // B, var 2
  ADREPORT( 1.0 - 1.0/(1.0+exp(-(int_1 + tau_12))) );                              // C, var 2

  ADREPORT( 1.0/(1.0+exp(-int_0)) );                                               // A, var 3
  ADREPORT( 1.0/(1.0+exp(-int_1)) - 1.0/(1.0+exp(-int_0)) );                       // B, var 3
  ADREPORT( 1.0 - 1.0/(1.0+exp(-int_1)) );                                         // C, var 3


  // Log-odds for each rating x variety, so that confidence intervals for them can be calculated on the log scale
  // These are in the same order as the probabilties above
  ADREPORT( int_0 + tau_01 );                                    
  ADREPORT( log( (1.0/(1.0+exp(-(int_1 + tau_11))) - 1.0/(1.0+exp(-(int_0 + tau_01)))) / ( 1 - (1.0/(1.0+exp(-(int_1 + tau_11))) - 1.0/(1.0+exp(-(int_0 + tau_01)))) ) ) ); 
  ADREPORT( -int_1 - tau_11 );                              

  ADREPORT( int_0 + tau_02 );                                    
  ADREPORT( log( (1.0/(1.0+exp(-(int_1 + tau_12))) - 1.0/(1.0+exp(-(int_0 + tau_02)))) / ( 1 - (1.0/(1.0+exp(-(int_1 + tau_12))) - 1.0/(1.0+exp(-(int_0 + tau_02)))) ) ) );
  ADREPORT( -int_1 - tau_12 );                              

  ADREPORT( int_0 );                                               
  ADREPORT( log( (1.0/(1.0+exp(-int_1)) - 1.0/(1.0+exp(-int_0))) / ( 1 - (1.0/(1.0+exp(-int_1)) - 1.0/(1.0+exp(-int_0))) ) ) );                       
  ADREPORT( -int_1 );                                         

  // contrasts
  ADREPORT( tau_01 - tau_11 );   // two contrasts to jointly test separate variety effect by link
  ADREPORT( tau_02 - tau_12 ); 
  ADREPORT( tau_01 ); // four estimates to jointly test treatment effect
  ADREPORT( tau_11 ); 
  ADREPORT( tau_02 ); 
  ADREPORT( tau_12 );

  // variance components 
  ADREPORT( sdb  * sdb );   // blk variance
  ADREPORT( sdbt * sdbt );  // blk*trt variance

  return nll;
}

Next, the model is compiled and loaded. Initial values for the parameters are defined, matching those specified in PROC NLMIXED. The function MakeADFun() constructs an objective function that will calculate the negative log-likelihood and its gradient. The optim() function is used to minimize the negative log-likelihood, using BFGS, a quasi-Newton technique. The sdreport() function is used to calculate standard errors of all the model parameters, including the additional contrasts and estimates specified in the template. The covariance matrix of all the additional estimated quantities is generated using the delta method.

Appendix E: Using TMB to obtain F-tests equivalent to SAS PROC NLMIXED output

For the non-proportional-odds model, it is possible to post-process the output from the R TMB model to obtain the same contrasts as in SAS PROC NLMIXED, in which F-tests are used to jointly test the null hypotheses that (1) the variety effects for each category threshold are not different from one another and (2) the individual category-specific treatment effects are all zero. We extract the covariance matrix that was generated for the estimated quantities using the delta method and generate an F-statistic using the estimates of the contrasts and their covariance matrix. Following PROC NLMIXED, the numerator degrees of freedom is the number of contrasts, and the denominator degrees of freedom is the number of parameters in the model.

contrast_Ftest_likeSAS <- function(report, contrast_names) {
  contrast_idx <- which(names(report$value) %in% contrast_names)
  cest <- report$value[contrast_idx]            # Estimates of each contrast
  VC <- report$cov[contrast_idx, contrast_idx]  # Covariance matrix of the contrasts
  W <- as.numeric(t(cest) %*% solve(VC, cest))  # Chi-squared statistic
  df <- length(cest)                            # Numerator df (number of contrasts)
  p_fixed <- length(report$par.fixed)           # Denominator df (number of parameters)
  
  Fstat <- W/df                                             # F-statistic (Chi-squared/number of contrasts)
  Fpval <- 1 - pf(Fstat, df1 = df, df2 = p_fixed)           # p-value associated with F-statistic
  c(df1 = df, df2 = p_fixed, Fstat = Fstat, Fpval = Fpval)  # Return result
}

Appendix F: Non-proportional odds model implemented in Stan

The Bayesian implementation using brm() above uses the pre-defined multinomial response distribution and category-specific effect syntax. However, users interested in the Bayesian implementation of the non-proportional odds model may be interested in a direct translation of the likelihood statements of the SAS PROC NLMIXED model into the Stan language.

The Stan code below was written by copying and minimally modifying the key parts of the PROC NLMIXED code. The same weakly informative priors are used as for the brm model above. This model does not assume proportional odds. The model with proportional odds could be obtained with a small modification: combine tau_01 and tau_11 into one parameter, likewise with tau_02 and tau_12.

data {
  int<lower=1> N;
  int<lower=1> N_growers;
  int<lower=1> N_varieties;
  array[N, 3] int<lower=0, upper=1> Rating; // 1=C 2=B 3=A. Must be 2d array because of how multinomial distribution is defined.
  array[N] int<lower=1> Variety;
  array[N] int<lower=1> Grower;
}

parameters {
  // Intercepts (associated with the reference level, rating C)
  real int_0;
  real int_1;
  
  // Category-specific (specific to each rating threshold) effects for varieties 1 and 2
  real tau_01;
  real tau_11;
  real tau_02;
  real tau_12;
  
  // Standard deviations of random effects
  real<lower=0> sd_g; // Called sdb in the original SAS code. (block = g for grower and treatment = v for variety)
  real<lower=0> sd_gv; // Called sdbt in the original SAS code.
  
  // Individual random effects
  vector[N_growers] g; // Called blk_j in the original SAS code. This is the random effect for each grower.
  array[N_varieties] vector[N_growers] gv; // Called  bt_1j, bt_2j, and bt_3j in the original SAS code. This is the random effect for variety within grower.
}

transformed parameters {
  // Linear predictors (there are two link functions because k=3 levels of Rating)
  vector[N] eta_0;
  vector[N] eta_1;
  // Parameters of the multinomial distribution (probabilities of each rating)
  vector[N] Pi_0;
  vector[N] Pi_1;
  vector[N] Pi_2;

  for (i in 1:N) {
    // Two linear predictors because there are three levels of rating.
    eta_0[i] = int_0 + tau_01*(Variety[i]==1) + tau_02*(Variety[i]==2) + g[Grower[i]] + gv[Variety[i]][Grower[i]];
    eta_1[i] = int_1 + tau_11*(Variety[i]==1) + tau_12*(Variety[i]==2) + g[Grower[i]] + gv[Variety[i]][Grower[i]];
    
    // Apply inverse link function to linear predictors. Ensure that Pi1 is not negative.
    Pi_0[i] = 1/(1+exp(-eta_0[i]));
    Pi_1[i] = max([0.0, 1/(1+exp(-eta_1[i])) - 1/(1+exp(-eta_0[i]))]);
    Pi_2[i] = 1-Pi_0[i]-Pi_1[i];
  }
}

model {
  // Priors. Weakly informative to enable model convergence (just constrain the values to a reasonable order of magnitude)
  sd_g ~ gamma(1, 1);
  sd_gv ~ gamma(1, 1);
  int_0 ~ normal(0, 10);
  int_1 ~ normal(0, 10);
  tau_01 ~ normal(0, 10);
  tau_11 ~ normal(0, 10);
  tau_02 ~ normal(0, 10);
  tau_12 ~ normal(0, 10);
  
  // Likelihood
  for (i in 1:N) {
    Rating[i] ~ multinomial([Pi_0[i], Pi_1[i], Pi_2[i]]');
  }
  g ~ normal(0, sd_g); // Because covariance of random intercept and random slopes is 0, we can treat them as separate normals instead of a multivariate normal
  for (i in 1:N_varieties) {
    gv[i] ~ normal(0, sd_gv); 
  }
}

generated quantities {
  // For each posterior sample, generate the estimated marginal probability of each rating for each variety
  // This is not conditioned on random effects.
  real pAv1 = 1/(1+exp(-(int_0+tau_01)));
  real pBv1 = 1/(1+exp(-(int_1+tau_11)))-1/(1+exp(-(int_0+tau_01)));
  real pCv1 = 1-(1/(1+exp(-(int_1+tau_11))));
  real pAv2 = 1/(1+exp(-(int_0+tau_02))); 
  real pBv2 = 1/(1+exp(-(int_1+tau_12)))-1/(1+exp(-(int_0+tau_02)));
  real pCv2 = 1-(1/(1+exp(-(int_1+tau_12)))); 
  real pAv3 = 1/(1+exp(-int_0)); 
  real pBv3 = 1/(1+exp(-int_1))-1/(1+exp(-int_0));
  real pCv3 = 1-(1/(1+exp(-int_1)));
}
