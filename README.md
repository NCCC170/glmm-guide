# GLMM Guide

## Directory Structure

### `data/`

Where are all data lives: either as .xlsx, .csv or .txt files. All files should be named as thus:

`example_01.csv`

Where it is all lowercase, followed by a single underscore and 2-digit number so the examples will order themselves properly. 

### `scripts/`

All plain scripts, either as .R, or .SAS files (at this time). These are a stripped-down version of the worked examples including code to run the examples, but lacking the explanation provided in the worked examples.Each file should contain the code for one example. All files should be named as thus:

`example_01_R.r`
`example_01_SAS.SAS`

This is largely following the convention of the data files naming system, with an "_R" or "_SAS" appended to the file names. 



### `chapters/`

A filled out template, one for each example, working out the design process, the . All files should be named as thus: 

`example_01.qmd`

### All other files

***Please*** do not alter any of these files.


### How to Contribute

We each are working on an example, starting with an example file, creating a .

#### If you want to work with GitHub and makes pull requests 

1. Fork the repository
2. Clone your fork of the repository locally
3. Follow instructions for package installation from renv
4. Communicate with team about what you are doing! What files are you working on? When do you think you will push your changes to the repository? 
5. Make changes to your repo
6. Commit changed with a short and descriptive commit message.
7. Push your changes to your GitHub repo fork
8. If needed, sync your fork with the NCCC170 version of the repo
9. Open a pull request for your changed with the NCCC170 version
10. Wait for the magic to happen (your changes will likel6y be accepted pending no merge conflicts)
11. Communicate with team: let them know you are finished with this task. If relevant, close the open issue. 

To repeat:

1. Make sure your fork is synced with the NCCC170 version
2. Start at step #4 above and proceed. 

#### If you don't want to work with GitHub

1. Download the repository locally
3. Open the .Rproj into RStudio and follow instructions for package installation from renv
4. Communicate with team about what you are doing! What files are you working on? When do you think you will provide your completed files? 
5. Provide completed files to the shared OneDrive 
11. Communicate with team: let them know you are finished with this task and uploaded your files

To repeat:

1. Make sure your fork is synced with the NCCC170 version
2. Start at step #4 above and proceed.
